# BUG-20261018-1736: First screen unlock fails on a stale notification session

## Reproduction

2026-10-18 MSK: swaylock challenge at 17:35:13 found Broken pipe and rebuilt
GATT at 17:35:15. Subscription returned at 17:35:22; sudo succeeded at 17:35:29.
Direct swaylock PAM test succeeded at 17:36:40. The actual swaylock binary in
an isolated headless Sway compositor succeeded through phone approval at
17:38:51 after an empty Enter. The PAM stack is already wired correctly.

## Expected

One registered GATT application survives ordinary disconnect/reconnect. Detect
notification-session closure before another challenge and replace only that
session when the phone subscribes again. Late closure must not clear a newer
writer. No approval, replay, nonce, bond, or SPEC D1–D8 changes.

## Root cause

`PersistentPeripheral` stores a CharacteristicWriter without observing closed().
`notify_challenge` detects the closed socket only on write, rebuilds the entire
application, disconnects adapter devices, and returns transport-error.

## Fix and verification

Add tested notification-session ownership and closure handling, use it in the
GATT control loop, and remove application rebuild from notification failure.
Preserve MTU chunking and per-challenge crypto. Qualify reconnect and first
unlock using the real headless locker, keeping the desktop session unlocked.

Implemented in `crates/syauth-transport/src/peripheral/notification.rs` and
`peripheral.rs`. The control loop observes the current writer's closed future
without holding its mutex; closure or failed send clears only that exact writer.
New subscriptions replace the writer without replacing GATT. MTU-sized sends
preserve the previous AsyncWrite chunking. Dead-writer application rebuild and
its cached bond-key field were removed. Initial registration still contains
the separate adapter-wide disconnect behavior identified in the recovery report.
