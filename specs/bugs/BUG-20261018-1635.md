# BUG-20261018-1635: Phone reports pairing failure after desktop commits bond

## Summary

The Android pair GATT exchange writes its key before reading the host key;
the desktop replaces the pair service on that write, causing the phone's
subsequent read to fail. Duplicate bond callbacks also repeat key generation.

## Reproduction

Real phone, operator-authorized test on 2026-10-18 16:28 MSK:

- Phone: BOND_BONDING → BOND_BONDED; duplicate mintKeystoreEd25519 messages;
  `pair-service exchange failed: host-pubkey read failed status=1` twice.
- Desktop: `pair: bond persisted`, followed by GATT app registration and
  disconnecting stale links before the phone read finishes.
- Desktop nevertheless reloads the new peer and later grants a biometric
  authentication, leaving desktop and phone UI state inconsistent.
- Regression: PairGattOrderTest fails with `pair service was replaced`.
- Regression: duplicate_bond_callbacks_exchange_keys_once observes 2 exchanges.

## Expected

Read the desktop key while its pair service exists, then write the phone
key to commit the exchange. Each pairing backend exchanges keys once.

## Root Cause

AndroidPairGattExchange sends the commit operation first. The daemon's
pair event consumer persists the peer and rebuilds its GATT application;
the previously discovered host characteristic can disappear before the read.
RealPairBackend also lacked an atomic guard against repeated bond callbacks.

## Fix

exchangePairPubkeys reads before writing; AndroidPairGattExchange uses that
ordering. An AtomicBoolean guards runPostBondExchange before key generation.
No UUID, key derivation, or authentication policy changed.
