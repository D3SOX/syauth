# BUG-20261020-0252: Wait for the documentation scene layout before recording it

## Summary

The browser checker can record a portrait view box as its desktop baseline before the scene's resize observer settles.

## Reproduction

- Command: `target/docs-venv/bin/python -u scripts/docs-check.py`
- Evidence: the mobile check failed with `Locator expected not to have attribute '0 0 420 840'`, because that portrait view box had already been recorded for the desktop unlock scene.
- A browser probe delayed `ResizeObserver` callbacks by 500 milliseconds. The checker recorded portrait view boxes for all three scenes despite their measured widths of 936 pixels; after the observer ran, all three layouts were landscape.

## Expected behavior

The desktop baseline is captured after each illustrated scene reaches its landscape layout. Narrow-screen checks then verify portrait reflow against that baseline.

## Actual behavior

Visibility alone allowed the checker to capture the initial portrait drawing before layout observation completed.

## Root cause analysis

Empty widgets are hidden by `.sy-mechanics:empty`. Their initial width is zero when mounted, so the first drawing is portrait. `ResizeObserver` subsequently draws the correct layout for the visible widget width. The checker waited for visibility, but visibility does not establish that the asynchronous observer has run.

## Fix

Wait for the desktop scene's `data-layout="landscape"` before recording its view box. Retain all existing mobile and tablet reflow assertions.
