# BUG-20261018-2106: Stable Rust CI fails lint

## Summary

The upstream `ci` workflow fails `make lint` on Rust 1.99.1 while its
workspace test and release build jobs pass.

## Reproduction

- Command: `gh run view 39157982608 --repo dmytrogajewski/syauth --log-failed`.
- Evidence: `syauth-transport` fails with ten `clippy::double_must_use`
  errors originating in `#[async_trait]` expansions.
- [Failing workflow](https://github.com/dmytrogajewski/syauth/actions/runs/39157982608).
- Local command: `cargo deny check`.
- Local evidence: RUSTSEC-2026-0370, RUSTSEC-2026-0371 and RUSTSEC-2026-0372
  reject `zvariant`, `zbus_names` and `zvariant_derive`, reached through
  `secret-service` 5.1.0 and `zbus` 5.15.0.

## Expected Behavior

The unchanged CI lint, test and release build gates pass with warnings denied
and the advisory policy enforced.

## Actual Behavior

Clippy stops the lint job before formatting and dependency checks can run.
The local dependency check independently exposes unmaintained dependencies.

## Root Cause Analysis

The lockfile selects `async-trait` 0.1.89, whose macro adds a bare
`#[must_use]` to methods already returning must-use futures. Rust 1.99
checks this generated code. The dependency's
[0.1.92 release](https://github.com/dtolnay/async-trait/releases/tag/0.1.92)
removes the redundant attribute. `secret-service` 5.1.0 retains the standalone
D-Bus type crates that were merged into `zbus` 6.

## Fix

- Require `async-trait` 0.1.92 in both direct consumers and refresh the lockfile.
- Remove two redundant formatting references in `tests/probe_pair_uuid.rs`
  exposed after the macro diagnostic is fixed.
- Update `anyhow` to 1.0.103 and `event-listener` to 5.4.2, fixing
  RUSTSEC-2026-0190 and RUSTSEC-2026-0221 respectively.
- Record exact exceptions for the three informational maintenance advisories
  in `deny.toml`. No compatible published Secret Service release removes
  these dependencies. Remove these exceptions after adopting the published
  zbus 6 migration tracked by
  [upstream PR #122](https://github.com/open-source-cooperative/secret-service-rs/pull/122).
- Acknowledge the unavoidable syn 2/syn 3 macro dependency duplication using
  the existing version-specific duplicate policy.

The encrypted Secret Service backend and kernel-keyring preference are retained.
No SPEC §3.2 D1–D8 or §3.3 requirement changes. The CI workflow, warning denial,
vulnerability checking and test coverage remain enabled.

## Verification

A minimal public async trait reproduces `clippy::double_must_use` with
`async-trait = "=0.1.89"` under Rust 1.99.1. Changing only the dependency
to `=0.1.92` passes Clippy with `-D warnings`.

With `RUSTUP_TOOLCHAIN=1.99.1` and `RUSTFLAGS='-D warnings'`:

- Local checkout: `make lint`, `make test` (472 passed, 8 ignored) and
  `make build` pass.
- An isolated snapshot of upstream `cfab0a68dbd541b8a4375191244cbccc5d1f3df5`
  with only the CI fix passes lint, `make test` (446 passed,
  8 ignored) and `make build`. The extra local `serde_json` dependency in
  `syauth-presenced` is excluded from the upstream lockfile change.
- The snapshot scope check uses the same forbidden-expression scan with `rg`,
  then `make -o scope-discipline lint`, because the archive has no Git metadata.
- All three release artifacts are present and executable:
  `libpam_syauth.so`, `syauth` and `syauth-presenced`.
- Clippy has no warnings. Stable rustfmt reports the existing nightly-only
  configuration notices; `cargo audit` reports the three informational
  maintenance advisories. Formatting and the configured dependency gates pass.

Upstream CI must run on a published commit before its status can be called green.

## Stressors and Validation

1. New Clippy diagnostics: reproduce with CI's Rust 1.99.1.
2. Older local compiler: select the validation toolchain explicitly.
3. Stale lockfile: inspect the resolved dependency graph.
4. Macro expansion changes: lint every workspace target and feature.
5. Async object compatibility: run the existing transport and daemon tests.
6. Secret Service compatibility: retain the kernel keyring and libsecret backends.
7. New advisory data: run the complete dependency check.
8. Transitive license changes: retain the existing license policy.
9. Formatting drift: run the CI formatting gate.
10. Release-only compilation: build the workspace in release mode and check artifacts.
11. Existing local changes: compare changed files against a saved baseline.
12. Unpublished changes: distinguish local validation from an upstream green run.
